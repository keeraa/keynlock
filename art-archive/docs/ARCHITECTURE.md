# Архитектура сцены архива картин

## Источник и результат сборки

```text
art-archive/
├── src/
│   ├── app/             самостоятельный запуск и жизненный цикл
│   ├── scene/           сборка сцены, камера, освещение
│   ├── architecture/    геометрия здания и материалы
│   ├── environment/     небо и адаптер облаков
│   ├── player/          движение, мышь, клавиатура, Pointer Lock
│   ├── rendering/       renderer, рисованный свет, обводка, батчинг
│   ├── ui/              меню, план, HUD, настройки
│   ├── localization/    словарь и перевод интерфейса
│   ├── persistence/     ключи и безопасное чтение настроек
│   └── debug/           линейки и измерение масштаба
├── config/              параметры сцены, камеры, рендера и облаков
├── styles/              стили по областям интерфейса
├── assets/              гуашевые WebP
├── vendor/              зафиксированные Three.js и Village Cumulus
├── tests/               геометрия, навигация, модули и ресурсы
├── scripts/             сборка и режим разработки
├── index.html           оболочка самостоятельного приложения
├── serve.mjs            статический локальный сервер
└── dist/                результат сборки, не источник
```

`npm run build` копирует `src` в `dist/js`, остальные публичные папки — в одноимённые папки `dist`. Бандлера, CDN и дополнительной копии движка нет. Относительные импорты работают и в исходной структуре, и в сборке. Скрипт удаляет устаревшие сгенерированные файлы вместе с предыдущим `dist`. `npm run dev` следит только за исходными папками, без цикла пересборки самого `dist`.

## Поток запуска

```text
index.html → app/bootstrap.js → app/application.js
                                  ├── rendering/create-renderer.js
                                  ├── scene/create-scene.js
                                  │   ├── architecture/create-building.js
                                  │   ├── architecture/layout.js + player/movement.js
                                  │   ├── scene/camera.js + lighting.js
                                  │   ├── environment/sky.js + clouds.js
                                  │   └── rendering/static-batches.js
                                  ├── player/controller.js + bind-input.js
                                  ├── ui/* + localization/* + persistence/*
                                  └── debug/scale-inspector.js
```

`bootstrap` загружает конфигурацию, один раз импортирует Three.js и показывает ошибку запуска. `application` связывает готовые системы, переключает режимы intro/play/pause/plan и владеет единственным `requestAnimationFrame`. Геометрии, формул движения, кода рисования табличек и раскладки меню в нём нет.

Публичная сцена не импортирует `app`, `ui`, хранилище браузера или файл движка. Перевод для 3D-табличек передаётся функцией `translate`; по умолчанию сохраняется исходный текст. Это позволяет подключить сцену к общему приложению с его движком, языком и игровыми часами. Проверка зависимостей закреплена тестом.

## Владелец ресурсов и выход из сцены

- `architecture/context` регистрирует геометрию, материалы и текстуры табличек. Строители получают контекст и добавляют только свою часть здания.
- `architecture/materials` хранит одну текстуру на URL и освобождает её при выходе. Общая геометрия не создаёт копии движка.
- `static-batches` владеет объединёнными геометриями. Крыши и верхние стены объединяются отдельно, поэтому план может их скрывать.
- `createArchiveScene().dispose()` последовательно освобождает облака, батчи, здание, материалы, небо и освещение. Повторный вызов безопасен.
- `application` освобождает интерфейс и ввод, отменяет кадр, затем освобождает сцену и renderer. `app/lifecycle` снимает зарегистрированные обработчики через AbortController и выполняет очистку в обратном порядке.
- Pointer Lock освобождается при выходе. Поздний успешный захват после удаления приложения также снимается.
- При переключении языка текстуры табличек обновляются на месте. Построение здания заново не требуется.

Стабильные ключи сохранения: `keynlock-art-archive-controls-v1`, `keynlock-art-clouds-v1`, `keynlock-art-language`. Рефакторинг не меняет формат ранее сохранённых настроек.

## Подключение к общему особняку

Пример для браузерного хоста со своим renderer и уже загруженным `THREE`:

```js
import {createArchiveScene} from './js/scene/create-scene.js';

const world = createArchiveScene({
  THREE,                       // существующий экземпляр движка
  config,                      // содержимое config/scene.json
  cloudSettings: savedClouds,  // необязательный объект
  translate: hostTranslate,    // необязательная функция текста
});

// В существующем цикле хозяина:
world.clouds.update(dt);
renderer.render(world.scene, world.camera);

// Вид сверху:
world.building.setCutaway(true);
world.clouds.setVisible(false);

// При смене языка функция hostTranslate должна возвращать новый перевод:
world.building.refreshLanguage();

// При окончательном выходе:
world.dispose();
```

В этом варианте `app/bootstrap.js` не подключается. Управление и интерфейс хозяин может предоставить свои; `player/controller.js` и `player/movement.js` можно использовать отдельно. Фабрика не вызывает renderer или RAF. Она использует браузерный Canvas для неба и табличек, поэтому не является серверным рендерером без DOM.

Для самостоятельной версии используется `startArchiveApplication({THREE, config})`, возвращающий `{dispose()}`. Его очистка также вызывается на `pagehide`. Событие выхода у двери — `keynlock:art-archive-exit`; фактический переход в логово ещё должен выполнить хозяин.

## Каталог и предпросмотр

В `catalog/manifest.json` находятся устойчивые ID, ссылки на локальные WebP, размеры изображений, метаданные и исходное размещение. Сцена и редактор читают один манифест. Список доступных игровых стен редактор получает из `config/scene.json`. Исходный экспорт задаёт начальные отклонения от манифеста в `catalog/initial-selection.json`. После первой правки текущий отбор сохраняет браузер.

`src/paintings/exhibition.js` рассчитывает ряды и страницы экспозиции по доступной длине каждой тематической стены. `display.js` подгружает близкие картины через модуль Three.js из ZIP, переиспользует объекты по ID и освобождает текстуры при удалении. `src/ui/collection.js` связывает редактор, сцену и переход из карточки к работе. Параметры размеров, расстояния загрузки и числа текстур находятся в секции `paintings` файла конфигурации сцены. Ручное игровое развешивание остаётся отдельным этапом.

## Проверка

`npm test` пересобирает проект и запускает 32 проверки: доступность залов, навигация и реальная геометрия ступеней, стыки полов и сводов, свободные стены, размеры и стекло, неизменность Village Cumulus, движение/ресурсы облаков, RU/EN, очистка обработчиков и Pointer Lock, общий масштаб камеры и игрока, соответствие сборки исходникам и независимость публичной сцены от самостоятельного приложения.

После изменения геометрии дополнительно осмотрите стыки и лестницу в прогулке и на плане. После изменения UI проверьте оба языка и перезагрузку с сохранёнными настройками.
