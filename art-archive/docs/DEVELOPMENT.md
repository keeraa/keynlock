# Разработка и выпуск архива картин

## Одна исходная версия

`src/`, `config/`, `styles/`, `assets/`, `catalog/`, `vendor/`, `server/` — исходники и данные. `dist/` пересоздаётся; ручные изменения в нём не выпускаются. Ключи сохранений и ID картин сохраняем устойчивыми. Авторский отбор (`catalog/initial-selection.json`), исключения и прогресс игрока — разные данные.

Временные пакеты выпуска находятся в `.releases/`, браузерные снимки — в `test-results/`, локальные аналитические отчёты — в `reports/`; все три каталога исключены из Git. Старые ZIP и исследовательские прототипы не являются источником выпуска.

## Установка и проверки

```sh
cd art-archive
npm ci
npm run check
npx playwright install chromium
npm run test:browser
```

Node.js 24 указан в `.node-version`; версии браузерных инструментов закреплены в `package-lock.json`. `npm run dev` — единственный процесс, который следит за исходниками и обновляет `dist`; второй watcher на ту же папку не запускайте. `PORT=4186 npm run preview` может параллельно обслуживать результат этого же watcher.

Workflow `.github/workflows/art-archive.yml` запускает тесты, подготовку выпуска из коммита и браузерные сценарии на push/PR с изменениями игры или её общих аудиоресурсов. Снимки и проверенный пакет хранятся в артефактах запуска семь дней. Конфигурация браузера следует [рекомендациям Playwright для CI](https://playwright.dev/docs/ci).

Браузерные тесты используют новый профиль и `?playtest=qa`. Проверяют открытие меню, версию и настройки, подъём/рассмотрение/оставление тяжёлой картины и сохранение после перезагрузки. Геометрия лестницы, вывоз огромных картин, обучение, углы и режимы дополнительно покрыты тестами на настоящих классах Three.js и навигации. Живую проверку перед плейтестом фиксирует [чек-лист](PLAYTEST-CHECKLIST.md).

## Воспроизводимый пакет

```sh
npm run release -- --commit HEAD
# либо конкретный коммит и отдельная папка:
npm run release -- --commit <полный-SHA> --output /tmp/art-archive-release
```

Скрипт берёт `git archive` указанного коммита, а не содержимое рабочей папки. Незакоммиченные изменения не попадут в выпуск. Список исходных зависимостей записан в `config/release.json`:

- сама папка `art-archive`;
- общий плеер `js/3d/core/audio`;
- музыкальные записи `js/3d/scenes/key-archive/dist/assets/music`.

Это историческое расположение канонических записей; сборка не требует запускать архив ключей. Все перечисленные файлы должны быть в выбранном коммите. Новые общие ресурсы добавляйте в этот список явно.

Результат: папка, `<папка>.tar.gz`, Worker, клиент, миграции, `release.json` и `release-manifest.json`. В манифесте — SHA-256 каждого файла. Перед упаковкой состав и идентификатор проверяются. Воспроизводится содержимое по коммиту; байты gzip-архива могут различаться из-за временных меток контейнера.

Детальные изображения берутся с неизменяемых GitHub URL этого же коммита, как в текущей опубликованной игре. Их наличие в исходнике проверяется; миниатюры, рамки, звук и код входят в пакет. Без сети детальная репродукция может остаться на локальном эскизе. Изменение этой политики требует отдельной проверки размера и загрузки.

## Публикация через Sites

Существующий проект указан в `.openai/hosting.json`. Не создавайте новый сайт для очередного выпуска. Основной коммит должен быть запушен. Репозиторий Sites содержит тонкую обёртку с `upstream.json`: она закрепляет этот SHA и вызывает **тот же `scripts/release-build.mjs`**. Своих правил обработки картин и звуков в обёртке нет.

Порядок: проверки → коммит и push → закрепить SHA в `upstream.json` → штатный помощник Sites собирает и пушит обёртку → сохранить версию с полученным SHA и архивом → опубликовать сохранённую версию. Успех подтверждается статусом `succeeded`. Номер Sites и коммит — разные идентификаторы; в меню игры отображается коммит исходников.

Учётные данные остаются в штатном процессе Sites, их не записываем в Git или npm-скрипты. CI готовит пакет, но сам не публикует сайт и не меняет аудиторию.
