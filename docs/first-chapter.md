# Журнал заказов — v372

Маршрут включает все миссии из каталога мира: сначала 28 заданий уровня 1,
затем 21 уровня 2 и 21 уровня 3. Нереализованные уровни не добавляются как
фиктивные повторения. При добавлении уровня в GameCatalog он автоматически
попадает в соответствующий круг. Первая механика каждого круга — Задвижки набережной.
Журнал открывает следующий заказ после завершения предыдущего; карта остаётся
свободным режимом игры со всеми поддерживаемыми сложностями. Первые десять
заказов образуют главу «Чужие подписи» с итоговой сценой; остальные обозначены
как дополнительные испытания. Проверка перехода — в
[отчёте](qa/chapter-ending-2026-09-09.md).

Иллюстрация первой локации показывает канал, набережную и лодки, без видимых
сооружений для постройки или ремонта судов. Заказ и название в каталоге
изменены на «Набережная». Технический ID `wharf` сохранён. Высота иллюстрации
увеличена на 30%: с 180 до 234 px на компьютере, с 135 до 175,5 px на телефоне.

## Конфигурация и несколько головоломок

`js/data/campaign.js` задаёт порядок первых механик, уровни и overrides.
`js/core/campaign-route.js` строит маршрут, проверяет поддерживаемые сложности,
управляет последовательностью и миграцией сохранений. `js/world/campaign.js`
отвечает за журнал и запуск через сервис миссий.

Сейчас в заказе одна головоломка. Пример конфигурации заказа из трёх:

```js
overrides: {
  'wharf-1': {
    steps: [
      {id:'main', mode:'wharf', tier:1},
      {id:'inner', mode:'keyprofile', tier:1},
      {id:'last', mode:'wharf', tier:1}
    ]
  }
}
```

`main` сохраняет зачёт существующей первой головоломки. Идентификаторы заказа
и шагов должны оставаться стабильными. Игрок видит номер головоломки,
получает результат после каждой и сам запускает следующую. Частичное
прохождение сохраняется при перезагрузке, заказ засчитывается после всех шагов.
Повторное прохождение также проходит по всей цепочке; незавершённый повтор
после перезагрузки начинается сначала, не отменяя основной зачёт.

Учебные варианты четырёх первоначальных механик действуют только на сложности 1.
Второй и третий уровни используют собственные параметры механик, не учебные.
Новые сюжетные события этой конфигурацией не вводятся.

## Сохранения

Ключ `keynlockFirstChapter` сохранён для совместимости с меню и слотами.
Версия 2 хранит `completedSteps` вида `wharf-1/main`. Старые четыре задания,
сохранённые как mode IDs, мигрируют в соответствующие шаги уровня 1. Победы
на других уровнях и в других шагах не могут засчитать текущую головоломку.
Перезапуск после поражения сохраняет orderId, stepId и сложность.

Новый сеанс начинается с трёх отмычек. Продолжение сохранения не восстанавливает
потраченные инструменты автоматически. Числа подписаны с правильным склонением:
«1 отмычка», «3 отмычки», «5 отмычек», «1 деталь», «2 детали».

Если отмычек нет, деталей меньше двух и монет меньше 30, верстак предлагает
разобрать старые заготовки бесплатно. Запас деталей доводится до шести;
«Заполнить футляр» создаёт из них три отмычки. Повторным нажатием нельзя
накапливать материалы. После пополнения проваленная миссия запускается заново.
Нулевой запас не закрывает доступ к логическим задачам, не требующим отмычек.

## Проверка

`npm test` проверяет существующие сценарии и дополнительные случаи:

- полный проход маршрута модели, порядок сложностей и блокировки;
- включение только реализованных комбинаций механики и сложности;
- миграцию старого журнала без открытия старших сложностей;
- три головоломки в заказе, частичный сейв, повтор одной механики с разными ID;
- повторное прохождение цепочки без утраты основного прогресса;
- старт с тремя отмычками и восстановление полного начального футляра;
- склонения и сохранение идентификаторов заказа при повторной попытке.

Проверка модели подтверждает доступность всей цепочки, но не означает,
что все 70 головоломок пройдены вручную. Баланс всех механик и реальная
длительность кампании требуют отдельного игрового тестирования.
