# Архив ключей · контракт KeyFactory

`dist/js/key-factory.js` — единственный API для создания ключей в игровых
системах. Активен `key-forge-adapter.js` с заготовками мастерской v16; резервный
`archive-legacy` сохранён в модуле. Подключение происходит **до** `createWorld()`
и не меняет игровую механику.

Профили десяти семейств находятся в `dist/assets/key-design-profiles.json`.
При старте `key-provider-entry.js` загружает их и создаёт адаптер. Изменение
профиля меняет геометрию при следующей загрузке игры, без миграции сохранений.
В мастерской чертежи пока сохраняются в `localStorage` другого сайта: для
автоматической общей публикации нужен синхронизатор профилей/серверное хранилище.

## Провайдер

| Метод | Возвращает / назначение |
| --- | --- |
| `createModel(type, { id, scale, variation, broken, mud, rust })` | `THREE.Object3D` для руки, ванн, анимаций и миниатюр; состояние покрытий принадлежит предмету |
| `getGeometry(type, { broken })` | Общий `THREE.BufferGeometry` для инстансинга на полу и в шкафу |
| `createGlyph(type)` | `THREE.Object3D` — символ формы на шкафу |
| `getPaint(type)` | `THREE.Texture` или `null`; обратная совместимость с Canvas/старой сценой |
| `getMaterial(type)` | Необязательный общий `MeshStandardMaterial` с Forge-шейдером металла, ржавчины и грязи |
| `getCrustGeometry(type, { broken })` | Необязательная общая геометрия непрозрачного грязевого ободка |
| `getCrustMaterial()` | Необязательный материал грязевого ободка с цветами верстака |
| `getRustStrength(type)` | Необязательная интенсивность ржавчины для загрязнённых предметов |
| `disposeModel(model)` | Необязательное освобождение временных instance-атрибутов без уничтожения общего металла |
| `getMetal(type)` | Строка названия металла; `steel` получает светлый оттенок |
| `getColor(type, context)` | Необязательный оттенок фиксированного металла из мастерской |
| `getColliderSize(type)` | `[ширина, высота, глубина]` в координатах сцены |
| `getDisplayScale(mode, type)` | Масштаб для `floor`, `hand`, `cabinet`, `bath` |
| `createFallbackStamp(type, broken)` | `CanvasImageSource` 160×220 или `null`; запасная картинка ключа в инвентаре, если 3D-снимок недоступен |

Ось Y идёт от зубцов к головке, лицевая сторона — +Z; модель центрирована
как в старом архиве. Геометрия должна содержать позицию и нормали; желательно
UV. Для тысячи ключей одна геометрия на семейство и состояние `broken`
переиспользуется в `InstancedMesh`. Провайдер не должен создавать новую
геометрию на каждый вызов `getGeometry`.

`key-instance-finish.js` добавляет к общим атрибутам геометрии только три числа
на экземпляр: интенсивность ржавчины, переключатель грязи и случайный seed.
Исходный Forge-шейдер использует их для каждого ключа отдельно. Грязевой край
инстансируется отдельной общей геометрией только для грязных предметов.
Постобработка мультяшного света сохраняет исходный Forge-материал, чтобы освещение не
удаляло шейдерные пятна. `key-thumbnails.js` один раз рендерит ключ в маленький
WebGL-target существующего рендера, кеширует снимки по состоянию и `id`.

У каждого ключа по-прежнему стабильные `id`, `type`, `variation`, `broken`,
`mud`, `rust`, `status`; сохранения не сериализуют геометрию. Состав десяти
семейств и правила сортировки находятся отдельно в `rules.js`.

При обновлении конструктора проверить: масштаб в четырёх контекстах,
выделение и попадание луча, надлом, коллизии, ванны, бросание, FPS на 1000
ключах и сохранение предыдущего прогресса.

Старые индексы `type` закреплены: Кольцо→Подвальный, Треугольник→Башенный,
Квадрат→Архивный, Ромб→Часовой, Пятиугольник→Астролябия,
Шестигранник→Кузнечный, Звезда→Алхимический, Клевер→Садовый,
Овал→Дворцовый, Корона→Братства. Они же определяют номер шкафа и уже
сохранённые `id`. Настройки `broken`, `mud`, `rust` принадлежат отдельному
предмету архива, хотя угол надлома берётся из профиля семейства.

Запасного 2D-рендера больше нет: без WebGL архив просит открыть его в браузере
с WebGL. `createFallbackStamp` остаётся только запасной картинкой ключа в
инвентаре; если провайдер возвращает `null`, слот показывает символ семейства.
