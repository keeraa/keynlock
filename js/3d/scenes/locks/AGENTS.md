# Keynlock · правила разработки

Проект — интерактивная 3D-лаборатория замков на Three.js r187. Интерфейс русский. Главная ценность — физически понятные механизмы и хорошо различимые **штифты**.

## При каждом изменении

1. Прочитать затронутые разделы `docs/architecture.md` и `docs/mechanics.md`.
2. Менять локальную подсистему; не переносить движение и игровые правила обратно в `main.js`.
3. Сохранять форму штифтов, контакт пружин, сопряжение шестерён, оси и посадку ключа/отмычки.
4. Не менять текущий внешний вид, цвета, компоновку и акцент на штифтах без явного запроса.
5. Если меняется механика, обновить тест и документацию. Если меняется изображение, обновить проверенную визуальную базу.
6. Выполнить `npm run release:check`; при доступном WebGL2 — `npm run test:browser` и `npm run test:visual`.
7. Новые игровые действия проводить через `createGameActions().dispatch`: тип команды → runtime-проверка → эффект → подписчики. Не писать обработчики игрового состояния в UI.

## Границы модулей

- `src/js/main.js`: только сборка зависимостей, подключение 3D-сцены и точка запуска; держать меньше 380 строк.
- `src/js/scene/lock-stage.js`: камера, рендерер, освещение, стол и OrbitControls; визуальные параметры не дублировать в `main.js`.
- `src/js/effects/lock-materials.js`: одна детерминированная карта шероховатости и базовые металлические материалы.
- `src/js/mechanisms/lock-hardware.js`: общие корпус, резьбовые винты, посадочные втулки, дужка, кулачок и приводной вал; режимы замков его переиспользуют.
- `src/js/mechanisms/`: 3D-сборщики и жизненный цикл `create/update/reset/dispose`.
- `src/js/mechanisms/pin-lock.js`: цилиндр и штифты; `pin-drive.js`: передача; `pin-tools.js`: отмычка/рукоять/натяжение. Следить за разделением обязанностей.
- `src/js/runtime/motions.js`: движение каждого типа замка, отдельно от общего кадра.
- `src/js/runtime/lock-animator.js`: общий такт, дужка, физика, сборка, рендер.
- `src/js/effects/cartoon-filter.js`: компоновщик двух независимых эффектов (toon, обводка); `drawing-shader.js` — общий экранный шейдер. В интерфейсе обводка по умолчанию включена (1 px); выключение эффектов возвращает прямой рендер.
- `src/js/effects/floating-particles.js`: тихая атмосферная пыль/морской снег на одном `THREE.Points`, движение только uniform времени; не расходует RNG головоломок и не попадает в нормальный проход обводки.
- `src/js/gameplay/`: головоломки, свободное вскрытие, переходы состояния.
- `src/js/gameplay/pin-ticker.js`: только покадровая симуляция мини-игр; обработка пользовательского ввода — в `pin-controller.js`.
- `src/js/gameplay/actions.js`: диспетчер всех внешних игровых команд; `commands.js`: валидация протокола.
- `src/js/ui/`: DOM, физические клавиши, выбор 3D-деталей и диагностика — только отправка команд.
- `src/js/ui/oil-tool-preview.js`: прямоугольник и дополнительный WebGL-проход для миниатюры маслёнки; не смешивать с каплями и вводом в `tools/oil-tool.js`.
- `src/js/ui/wrench-picker-preview.js`: единый дополнительный scissor-проход основного WebGLRenderer с пятью настоящими мешами натяжителей; не создавать пять контекстов и не менять материалы оригинальных инструментов при наведении.
- `src/js/ui/settings-tabs.js`: вкладки «Замок»/«Визуал» и управление фокусом вне игровой модели.
- `src/js/ui/oil-tool-input.js`: отдельные события мыши, клавиш, capture и переключение маслёнки; `tools/oil-tool.js` отвечает только за попадания по геометрии, капли и масляные следы.
- `src/js/types/contracts.d.ts`: типы игровых команд и жизненного цикла механизмов; `npm run typecheck` выполняется в каждой проверке.
- `src/js/runtime/scenarios.js`: совместимая точка экспорта сценариев и записей действий.
- `src/js/runtime/scenario-model.js`: seed и URL; `action-tape.js`: запись и повтор; `scenarios.js`: совместимая точка экспорта.

## Инварианты

- Верх вращающейся штифтовой сердцевины имеет 4–6 радиальных открытых гнёзд, строго совмещённых с нижними штифтами; `geometry/pin-bores.js` задаёт радиус и физически видимые внутренние стенки, шейдер `mechanisms/pin-lock.js` удаляет поверхность над отверстиями, а `ui/scene-pointer.js` учитывает это при кликах. При смене числа штифтов гнёзда перестраиваются вместе с ними.
- При 0% прозрачности инспекционное окно обязано быть непрозрачным и писать в буфер глубины, иначе обводка внутренностей проступает через металл. Схематичное просвечивание включается отдельной кнопкой «Рентген · схема», ручная/автоматическая прозрачность сохраняется при его выключении.

- В меню рисованных материалов доступны пять вариантов (3 стальных, 2 тёплых); специализированные фактуры шестерён, штифтов и блока пружин автоматически применяются без декоративных карточек. Для маленьких штифтов контраст пигмента снижен и мазки крупнее, для меди UV-обёртка замыкается симметрично в двух повторах. Разнос при 200% усилен, но винты сохраняют согласованное осевое перемещение и вращение.

- При свободном падении дужка должна быстро опрокидываться на бок: из фактической позы отпирания до положения лёжа менее 1,05 с, остановка менее 2,15 с при 16/33/40 мс. Не замедлять этот переход контактным затуханием.

- Четыре типа замка: `pin`, `disc`, `code`, `plate`; восемь штифтовых мини-игр с тремя уровнями.
- `plate` — «Пластинчатый», отдельная механика «Классика»: от четырёх до шести сплошных пластин с семью изолированными отверстиями. На всех один общий случайный знак из пяти; для движения штифтов нужен натяжитель с этим знаком из общего нижнего ряда пяти инструментов штифтового замка. 3D-отмычка и натяжители переиспользуются без дублирования исходных мешей и материалов.
- У штифтов 4–6 реальных пар; количество задаёт исключительно выбранная сложность (I/II/III, включая свободный режим: 4/5/6). Команда `pin-count` остаётся только для совместимости записей. Увеличенный рабочий ход сохраняет линию среза и контакт с пружиной.
- Во всех восьми штифтовых мини-играх A/D и ←/→ перемещают отмычку между штифтами. W/S и ↑/↓ меняют высоту или усилие там, где это применимо; W/↑ и пробел запускают действие в режимах подброса и резонанса. Клавиши кодируются через `event.code`.
- Замок открывает целая дужка; деталь возвращается без накопления смещений при сборке/сбросе. Дужка остаётся круглой и U-образной при падении: не переставлять компенсацию depth-scale после поворота; радиус прута 0.148, зазор до стенки отверстия 0.013. После свободного хода из гнёзд (~0.5 с) ускоренно отпускается в физическую симуляцию; тряска запертой дужки низкочастотная. Для тяжёлой дужки проверяются малый отскок, трение и конечная остановка на столе.
- Роспись рукоятки хранится отдельно в `src/assets/handles/japanese/` (метаданные `collection.json`, рабочая карта `geisha-red-fan.webp`); мастер сохранён в `art/handles/japanese/`. На рукоятке **один** окрашенный `LatheGeometry` без отдельной накладки на деревянную основу: у торца нет оголённого круга и зубчатого стыка. Два сюжета по окружности, укороченная шейка, кольцо на её конце. Стальной стержень входит внутрь нового короткого горлышка. Старые `geisha-handle*.webp` сохранены для истории.
- Клавиши обрабатывать через `event.code` для работы в русской и английской раскладках.
- Диагностические элементы доступны только с `?debug=1`; обычному игроку не мешают.
- `dist/` — результат `npm run build`, не место ручного редактирования.
- Все ассеты локальные; приложение должно работать без сетевых импортов.
- Оба экранных слоя включаются через `cartoon-toggle`; отдельно через `toon-toggle`, `outline-toggle`. У каждого два параметра с семантическими командами. Постэффекты не меняют геометрию или исходные материалы механизмов; буфер нормалей выделяется только для обводки. Старые команды бумажной фактуры и удалённого плёночного фильтра сохраняются как пустые операции для повтора записей. Гуашевых WebP восемь: пять переключаемых для обычных металлов и три для шестерёнок, штифтов и пружинного блока. Направляющие шариков не должны создавать висящие контуры в инспекционном разрезе.
- Запись/повтор должны использовать семантические команды, а не CSS-селекторы; чтение старых записей поддерживается отдельно.

## Перед публикацией

Сверить `git diff`, сборку, тесты, игровую функциональность и бюджет `reports/bundle.json`. Для 3D-изменений прогнать реальные скриншоты в Chromium с WebGL2. В отсутствие такого браузера честно отмечать визуальную проверку как незавершённую.

Подробнее: `docs/architecture.md`, `docs/quality.md`.
