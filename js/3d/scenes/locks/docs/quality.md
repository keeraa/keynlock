# Проверки качества и выпуск Keynlock

## Единый цикл

```bash
npm ci
npm run release:check
npm run serve
```

Затем в браузере с WebGL2:

```bash
npm run test:browser
npm run test:visual
```

`release:check` собирает статику, выполняет `npm run typecheck` (TypeScript/JSDoc без генерации JS), проверяет синтаксис, архитектурные ограничения, диспетчер команд, 3D-геометрию, физику, логику и все 24 настройки мини-игр. `test:browser` проверяет настоящий WebGL, UI и собирает отчёт `reports/browser-benchmark.json`.

`test:visual` открывает девять фиксированных сцен (разные штифты, ключ, разборка, две мини-игры, диски, кодовый и пластинчатый замки), сохраняет PNG и манифест в `reports/visual/`. Помимо полных скриншотов сохраняются снимки одного WebGL canvas и сравниваются шесть контрольных пар 3D-состояний (не учитывая различающиеся подписи меню). Если пара отличается менее чем на 0,5% пикселей, тест падает даже без эталонов. Для строгих GPU-регрессий:

1. В проверенном WebGL2-окружении выполнить `npm run visual:baseline` и просмотреть девять PNG в `tests/visual-baselines/`.
2. Добавить принятые базовые PNG в git.
3. Выполнять `npm run visual:verify`: сравнение каждого PNG с базовым снимком через ImageMagick, максимум 2% изменённых пикселей (настраивается `KEYNLOCK_MAX_VISUAL_DIFFERENCE`).

Если базовые PNG ещё не созданы, `test:visual` проверяет запуск WebGL, отсутствие пустых кадров и различимость шести пар 3D-сцен; CI предупреждает об отсутствии утверждённых эталонов. Полноценные попиксельные регрессии до утверждения эталонов остаются открытым пунктом. Создание эталонов выполняется только после успешных проверок всех сцен; браузер, который не может создать WebGL2-контекст, для этого не подходит. Без WebGL2 можно выполнять весь `release:check`, но нельзя достоверно подтвердить визуальный итог.

## Критерии завершения изменения

- У цилиндра реально видны отдельные радиальные входы 4–6 штифтов: центральная поверхность над ними вырезана шейдером, а под ней есть кромка и глубокая цилиндрическая стенка. При смене количества каналы совпадают со штифтами и скрываются/открываются вместе с ними; выбор штифта мышью не блокируется невидимой частью цилиндра.
- При 0% прозрачности инспекционная стенка полностью перекрывает внутренние линии: материал участвует в непрозрачном проходе и пишет глубину. Отдельная кнопка «Рентген · схема» позволяет смотреть сквозь неё; после выключения сохраняются ручное значение прозрачности и режим автопрозрачности. Переключение проверяется unit- и browser-тестами.

- После рефакторинга `main.js` содержит менее 380 строк и только соединяет подсистемы. Настройки камеры, света и стола принадлежат `scene/lock-stage.js`, базовые металлические материалы — `effects/lock-materials.js`, сборка корпуса и защёлки — `mechanisms/lock-hardware.js`. Четыре резьбовых винта делят одну геометрию; наконечники инструментов, физика дужки и все игровые команды остаются неизменными.
- Миниатюра маслёнки создаётся через `ui/oil-tool-preview.js`, управление — через `ui/oil-tool-input.js`. В обычном игровом кадре не считывается DOM-расположение её кнопки; после второго рендера всегда возвращаются параметры основного viewport и `autoClear`, включая случай ошибки. Удержание ЛКМ, pointer capture, Command-перетаскивание и Escape проверяются отдельно без WebGL в `tests/lock-factories.test.mjs`.
- Пять натяжителей в нижней панели отрисовываются поверх готовой сцены с очисткой только глубины и одной общей округлой 3D-подложкой. Выбранный и наведённый инструменты плавно поднимаются выше неё; область scissor захватывает дополнительное пространство над кнопками, поэтому верхушки не обрезаются. Отдельные кнопки не имеют подложек и градиентов. Под маслёнкой тоже есть округлая подложка, нарисованная за моделью в 3D; подпись под ней удалена. Рамки и подсветки по периметру нет, выбранное состояние показывает только маленький индикатор. Четыре металлических обода маслёнки проходят снаружи профиля кожаного корпуса и сохраняют непрерывный ровный контур без зигзагов на пересечении поверхностей.
- Атмосферные частицы постоянно, но медленно дрейфуют в 3D; 340 снежинок отрисовываются одним прозрачным `THREE.Points` с проверкой глубины. Они не отбрасывают тени, не перекрывают UI, не загрязняют контуры механизмов и не изменяют случайную генерацию головоломок. На кадр меняется только shader uniform времени; после `dispose` освобождаются геометрия и материал. Проверки — `tests/floating-particles.test.mjs` и `tests/cartoon-filter.test.mjs`.

- Задняя металлическая стенка повторяет скруглённый прямоугольный контур боковой обечайки, не выступает в четырёх углах, не образует отдельных овальных выпуклостей; тонкая фаска аккуратно соединяет торец со стенками. Полная толщина крышки сохраняется при разборке.

- Правила мини-игр и 3D-механизмы соответствуют `docs/mechanics.md`.
- В штифтовом замке число пар управляется сложностью I/II/III (4–6), даже в свободном режиме; отдельного выбора количества больше нет. После выбора перестраиваются реальные физические каналы, старые URL с семью штифтами ограничиваются шестью. Увеличенный подъём по-прежнему совмещает стык на линии среза, а пружина и верхний штифт непрерывно следуют за нижним.
- Запертая дужка покачивается с умеренной частотой, после отпирания быстро выходит из гнёзд и падает с физическим импульсом, вращением и контактом со столом; после поворота форма U и круглое сечение неизменны. На столе нет заметных повторных отскоков и бесконечной дрожи: после контакта дужка затухает и переходит в состояние покоя.
- Роспись рукоятки содержит читаемый профиль девушки, золотой веер и орнамент на красном лаке. Изображение по окружности повторяется ровно **дважды**, по одному разу спереди и сзади; закруглённый задний торец является частью того же окрашенного меша, без круга голого дерева и зубчатой границы между слоями. Горлышко короче и непрерывно сужается от корпуса до латунного кольца без изменения наклона на стыке; стержень входит под кольцо. Карта `assets/handles/japanese/geisha-red-fan.webp` находится в японской коллекции с сохранённым оригиналом; старые изображения не удалены.
- В «Пластинчатом» переключаются 4, 5 или 6 сплошных пластин с семью отдельными отверстиями; у каждой один прямой штифт с округлой верхушкой, без острого пика при виде сверху. На обеих сторонах всех пластин один общий рисунок, случайно выбранный из пяти исходных знаков: угол, колено, крючок, черта, вертикальная волна. Неверный инструмент блокирует смещение; верный позволяет переставить штифт через фазу втягивания/переноса/выдвижения. Дужка открывается только после установки всех штифтов на 4. Пластинчатый каркас полностью утоплен за лицевую стенку и не пересекает шарики дужки: отверстия чуть впереди шариков, боковые стойки обходят их по X. Сценарий `?scenario=plate&view=front` воспроизводим и присутствует в визуальных тестах.
- Геометрия остаётся непрерывной: винты с валами, шестерни без взаимного пересечения, пружины касаются штифтов.
- Выбор цвета, вставка инструмента, ход штифтов, разборка, сброс, освобождение дужки работают во всех режимах.
- `main.js` остаётся меньше 380 строк, а `dist/app.js` — менее 1,25 МБ (архитектурный тест).
- Нет ошибок JS, утечек новых геометрий и материалов; изображение сравнивается с предыдущим принятым эталоном.
- При переключении «Мультяшной рисовки» рендер и управление сохраняются; выключенный фильтр не создаёт дополнительных кадровых проходов. По отдельности и в комбинации проверить ступени света и контур по глубине/нормалям, два ползунка на каждый слой в WebGL2. Только обводка создаёт отдельный normal-pass; обводка по умолчанию включена на 1 px.
- Для художественной версии проверить мягкие ступени света, читабельные штифты и умеренные контуры без лишнего чёрного шума. Экранная бумажная фактура отсутствует.
- Для «Рисованных материалов» сравнить корпус, ключ, пружины, шестерёнки, штифты и блок пружин с выключателем в обеих позициях; проверить восемь настоящих WebP-текстур, выбор 3 холодных и 2 тёплых палитр, автоматическое подключение трёх специализированных фактур, три ползунка с дефолтами 95/90/2 и сохранение выбранных покрытий при возврате к исходным материалам. Мазки крупные и следуют за деталями; после выключения исходные `map`, `roughness` и `metalness` восстанавливаются. Каждая фактура создаётся и кэшируется при первом выборе без дополнительных рендер-проходов.
- Для всех пяти покрытий штифтов проверить плотный, приглушённый цвет гуаши и согласованность миниатюр с 3D-поверхностями. При отключении гуаши миниатюры переключаются на исходные металлические варианты. Дужка в закрытом положении строго симметрична относительно поперечной оси; обе ножки остаются прямыми, шарики и втулки не меняют посадку. Дужка состоит из одного непрерывного меша: нет светового или фактурного шва на переходе от прямой ножки к изгибу, на любом срезе радиус одинаков во всех направлениях, канавки для шариков являются частью геометрии; оба торца герметично закрыты плоскими непрозрачными крышками с наружными нормалями.
- Край общего блока пружин не задевает окружность зубьев ведущей шестерни даже при шести каналах. Шатун передаёт движение между двумя открытыми подшипниковыми кольцами: прямой металлический стержень подходит к внешним кромкам колец и не проходит сквозь текстуры валов.
- Глобальный тёплый фильтр и плёночное зерно полностью отсутствуют в HTML, CSS и рендере. Исторические команды `film-intensity` воспроизводятся как пустые операции.
- Проверить оба шарика при разборке и отпирании: нет висящих прямоугольных контуров старой открытой втулки, движение в карманы сохранилось.
- Колесо мыши над правой панелью прокручивает список настроек, не меняя масштаб камеры; на сенсорном экране панель прокручивается вертикальным жестом.
- Производительность на целевом устройстве контролируется через `?perf=1`. Количество draw calls и треугольников охватывает основной кадр, композитор и дополнительные WebGL-превью маслёнки/натяжителей. Лимиты устанавливаются после измерения эталонной машины, через `KEYNLOCK_MAX_DRAWS` и `KEYNLOCK_MAX_P95_MS`.
- `?debug=1` не меняет обычный интерфейс; seed и сценарии воспроизводятся.
- Все новые кнопки, клавиши и клики по 3D-деталям вызывают `gameplay/actions.js`. Семантические записи корректно проверяются и повторяются, а старые записи с DOM-селекторами остаются читаемыми.
- При добавлении новой команды обновить `types/contracts.d.ts`, `gameplay/commands.js` и тесты `tests/game-actions.test.mjs`, `tests/types.test.ts`.
- После изменений штифтового механизма проверить отдельно геометрию цилиндра, передачу и инструменты; после правки таймеров — тесты `pin-controller.test.mjs` для натяжения, резонанса, подброса и истечения времени.
- На торцевом круглом входе штифтового цилиндра виден непрозрачный утопленный вкладыш с настоящей узкой сквозной щелью. Радиус вкладыша слегка перекрывает край расточенного отверстия и устраняет боковые просветы; латунная окантовка и её гуашевое покрытие не изменены. Внутренняя щель совпадает с пазом сердцевины; ключ и оба инструмента могут войти без столкновения с заглушкой. Натяжной инструмент ниже основной отмычки, слегка смещён в глубину и имеет тонкий рабочий конец; пять его вариантов не пересекают основной стержень при движении и натяжении. Внешние части опущены ещё на 0.085, но кончики остались на прежней высоте внутри скважины. Левые концы первых двух натяжителей повторяют формы кнопок «<» и «┐».

- Проверка физики дужки: при реальном угле освобождения (−0.38 рад) и шагах 16/33/40 мс поворот на бок происходит менее чем за 1,05 с, полная остановка — менее чем за 2,15 с. Дужка не должна зависать на одной ножке.
- На штифтах мазки гуаши крупнее и приглушённее, миниатюры пяти покрытий соответствуют 3D. Медная фактура зеркально повторяется целое число раз и не образует шва вокруг цилиндров. В меню показаны только пять выбираемых вариантов, остальные три применяются автоматически. На максимальном разносе детали разъезжаются примерно на 36% дальше прежнего, при сборке точно возвращаются на места.

## Автоматизация

Регрессионный набор `tests/refactor-lifecycle.test.mjs` проверяет общий сброс состояния, безопасную замену геометрии ключа, идентичное скругление подложек, восстановление WebGL viewport даже при исключении, симметричное снятие DOM-слушателей и однократный `dispose` общих ресурсов. `tests/subsystems.test.mjs` дополнительно проверяет, что освобождение миниатюр не затрагивает рабочие геометрии натяжителей и удаляет капли/пятна масла из сцены.

`.github/workflows/quality.yml` содержит два независимых задания: build/unit и WebGL/screenshots в Chromium. В каждом запуске сравниваются контрольные пары WebGL-сцен; при наличии базовых PNG дополнительно включается обязательное сравнение с эталоном. Снимки сохраняются как артефакт для просмотра. Workflow запускается в репозитории GitHub с включёнными Actions; исходный репозиторий Sites сам по себе не гарантирует выполнение GitHub Actions.

Публикацию на ChatGPT Sites выполнять после успешных проверок и проверки `git diff`, с сохранением приватного доступа к проекту. Пакет для публикации строится из `dist/`; секреты и диагностические записи в него не добавлять.
